# Reach-Bridge v0.3.0

新增显式 NAS 浏览器兼容模式，在受限内核环境中复用现有 Chromium + OpenCLI，无需虚拟机或更换平台工具框架。

- `REACH_BRIDGE_BROWSER_SANDBOX=false`：在镜像统一启动入口中仅增加 `--no-sandbox`，强制非 root；默认 `true` 的标准模式不变，启动失败不自动降级。
- `REACH_BRIDGE_BROWSER_ENABLED` 继续独立控制是否允许浏览器动作；原生模式仍不启动浏览器。
- WebUI、渠道发现与 bootstrap 显示所选 sandbox 设置，兼容模式给出可见提示。
- 镜像启动入口保留上游 CDP pipe 文件描述符、信号、专用 profile 和生命周期；兼容模式的显式依赖准备会切换旧浏览器选择，但不清除会话或平台策略。
- Compose 新增 `REACH_BRIDGE_SECURITY_OPT`，标准值仍为随包 Chromium seccomp 配置；受限 NAS 使用 `no-new-privileges=true`，不添加 `SYS_ADMIN`、特权容器或 Docker socket。
- CI 在 amd64、arm64 分别验收标准 / 兼容模式的实际 Chromium 参数、OpenCLI 扩展、HTTPS 登录画布及点击、输入、按键、滚动、刷新。

## NAS 配置

```dotenv
REACH_BRIDGE_BROWSER_ENABLED=true
REACH_BRIDGE_BROWSER_SANDBOX=false
REACH_BRIDGE_SECURITY_OPT=no-new-privileges=true
```

保留现有 `.env`、非 root 用户、渠道配置及完整 `data/home`。已有自定义 Compose 需要转发新增 sandbox 环境变量，并替换原自定义 seccomp 引用。重建服务后，在 WebUI 对所需平台执行“准备依赖”，由本人登录并验收真实站内搜索。当前 Cookie、平台访问限制和限流仍由实际动作验证。

DS220+、DSM 7.4.1-90080 Update 1、Linux 4.4.302+ 已通过非 root 临时 Chromium + CDP + JavaScript/DOM 验证。该测试不包含真实账号登录或平台搜索。

关闭浏览器内部 sandbox 会降低会话与容器内数据的隔离保护；仅在接受此取舍的专用环境启用。恢复标准模式须改回 sandbox 与 seccomp 设置并重新创建服务；不会自动修改宿主设置或现有 NAS 项目。
